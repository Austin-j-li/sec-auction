### Formality scoring convention (fixed here, applied to all)

- A candidate with no formality label on a bid = wrong on both.

## K. Addendum: scoring clarifications written after the candidates were opened (no reference FACT above was changed; each rule is applied identically to all six)
1. Row citations in the notes use the spreadsheet row number shown in the dumps (`--- row N`); the ledger's own `#` is N-1.
2. Formality in the candidates is two columns (Formality = Formal/Informal, Conditions = None/Light/Heavy). RAW = the Formality column. MAPPED = Formality, except Formal + Heavy becomes Informal. Both are compared with Alex's labels in section A.
3. P12 price: low = high = 21.50 with the 19.00 cash / 2.50 options split in the row = right. Low 19.00 / high 21.50 entered as a "bidder range" = wrong (the filing has no range; a midpoint or a low-bound read gives a number Party B never offered), even if the text explains it.
4. "Round 4" for the exclusivity / definitive-negotiation stage: the reference has three rounds, so any ledger with a Round 4 row scores rounds_count_right = false. P13 placed in such a Round 4 is scored as wrong round (it is a numbered bidding round the reference does not have); P13 in Round 3 is right. The notes say whether the extra round holds any bid.
5. Counts: a count is right if the correct number is stated in a ledger row and the ledger's own Count cells for that event type do not add to a different total. Count cells that are explicitly partial (only named parties tallied, the 50 stated in text) are accepted but noted. A raw sum that double counts a party is scored wrong for the total even if a Summary note discloses it, because the rubric names double counting.
6. An exit row that appears ABOVE the same party's entry row (NDA) is an exit-before-entry, reported under item 3 only. It is NOT counted in order_inversions (item 4 is about pairs of bid or exit rows, per section J, and the filing gives no chronology for the 16 undated signings) and does not by itself flip signers_accounted_once.
7. Checklist point 2(a) follows Alex's words ("these numbers appear ... but the event itself is not recorded"): it is met only if the ledger has contact-event rows carrying 15 strategic + 35 financial = 50. A ledger that states 50 = 15 + 35 only inside the text of its round-opening row has the count but not the event, so 2(a) fails and point 2 as a whole is 'partly'.
